# Security Policy

Please do not post secrets, credentials, private user data, or exploitable security details in public issues.

For security-sensitive reports, use a private channel available through the repository owner or GitHub security advisory workflow when enabled.

APH is a governance/template project, but security issues may still matter when they could cause adopters to:

- leak credentials or personal data;
- bypass Human Gates;
- execute untrusted feedback as instructions;
- weaken release/recovery controls;
- claim false verification state;
- grant excessive tool or production authority to the wrong role.

A security fix should include a regression check or behavioral eval when practical.
